MODmain(argc, argv) · CBS 独立入口

把原本依赖完整 GAMBIT 配置的启动过程收拢成一个可独立运行的 CBS 进程编排入口。

  • 解析 CLI 状态并初始化 Nulike、可选 FullLikes/Rivet/Contur、日志、随机数和启动 banner。

  • 手动连接 functor/loop-manager 依赖，分流单文件与 batch，最后统一调用屏幕/JSON 输出和异常处理。

证据：ColliderBit/examples/solo.cpp:71–587；开发总结 §5.1。

  • 增加统一的 check_cutflow 和 check_histogram 运行时开关。

  • 在输出前检查路径是否有效，并由输出模块创建父目录。

MODSelect functors · Functor 选择

把 standalone 输入和 CBS 设置映射到实际执行所需的 GAMBIT functor。

  • 在 regular likelihood 与 FullLikes 之间选择 calcLogLikes。
  • 固定使用 CBS 的 HepMC reader、HEPUtils converter 和 CollectAnalyses。
  • 把 cutflow、printer 和 likelihood 参数传给对应 functor。

证据：ColliderBit/examples/solo.cpp:359–432。

MODResolve functor graph · 依赖连接
SUBFLOW · DEPENDENCY WIRINGfunctor handles→resolveDependency→resolveBackendReq→resolveLoopManager→nested_functions[]

新增 standalone 场景下的显式依赖 wiring，使 CBS 不依赖完整 GAMBIT scan 来组装调用关系。

  • 调用 resolveDependency 连接 event、detector、analysis、collection 和 likelihood。
  • 按配置连接 Nulike/FullLikes backend requirements。
  • 连接 loop manager，并将 Rivet/Contur 等 nested functions 加入 nested list。

证据：ColliderBit/examples/solo.cpp:448–535。

MODConfigure CBS policy · Loop 配置
SUBFLOW · CBS LOOP POLICYYAML settings→analyses + event limits→convergence = false→use_colliders=[CBS]→operateLHCLoop

为外部 HepMC 文件定义 CBS 专用的事件循环策略。

  • 传入 analyses、事件上下限和 use_colliders=[CBS]。
  • 把 run_convergence_checks 固定为 false，保证处理用户提供的完整 event file。
  • 把文件名、jet collections 和 cross section 传到 reader/converter/xsec functor。

证据：ColliderBit/examples/solo.cpp:380–407。

ADDSoloBatch::run_and_merge() · Batch 分支
SUBFLOW · BATCH MERGEprocesses[]→validate xsec + files→per-file subprocesses→weighted merge→recompute likelihood→sampling advice

把 CBS 从单个 event-file runner 扩展成多文件、多 process 的 batch runner。

  • 每个物理文件作为子任务运行，并保留所属 process 的完整截面。
  • 同一 process 内按事件数加权，跨 process 合并 signal、MC 误差和 histogram/cutflow 结构。
  • 合并后重新计算总 likelihood，而不是直接相加 per-file loglike；同时生成 sampling_advice。

证据：ColliderBit/examples/solo.cpp:248–343；开发总结 §5.4；03d5a9e959、3599c668e1。

MODoperateLHCLoop() · CBS Loop 集成
SUBFLOW · LOOP LIFECYCLECBS options→reset_and_calculate→event iterations→COLLIDER_FINALIZE→event_count + results

把 standalone CBS 配置接入 GAMBIT 的公共 loop lifecycle，并把事件数和 finalize 结果带回 CBS。

  • 使用 CBS collider 名称和 MCLoopInfo 保存 iteration/event_count。
  • 循环结束后读取 event_count.at("CBS")，进入结果收集和 likelihood。

证据：ColliderBit/examples/solo.cpp:545–559；ColliderBit/src/ColliderBit_eventloop.cpp:101。

ADDgetHepMCEvent · HepMC 读取
SUBFLOW · HEPMC READERhepmc_filename→read_event→event / EOF→report_end + halt→GenEvent

新增面向外部 HepMC 文件的事件读取路径，并把 EOF 变成 loop 的正常停止条件。

  • 从 YAML 取得文件名，在 OpenMP critical 区域读取下一个 event。
  • 检测空 event/文件结束，调用 report_end_of_event_file() 和 halt()。
  • 保留 event weight，并将读取结果交给统一转换器。

证据：ColliderBit/src/getHepMCEvent.cpp:160–219。

MODconvertHepMCEvent_HEPUtils · 事件转换
SUBFLOW · EVENT CONVERSIONGenEvent + weight→jet settings→convertParticleEvent→HEPUtils::Event→jets + MET

扩展 HepMC 到 HEPUtils 的转换，使 standalone CBS 使用与原有 ColliderBit 一致的对象和 jet 语义。

  • 读取 jet pT threshold、普通 jet collections、tau collection 和 Variable-R 配置。
  • 保留 event weight，调用统一 convertParticleEvent 生成 HEPUtils event。
  • 处理 special loop iterations，避免在没有真实 event 时解引用空依赖。

证据：ColliderBit/src/getHepMCEvent.cpp:193–242；开发总结 §5.6。

MODDetector/event branch · 探测器分支
SUBFLOW · DETECTOR BRANCHHardScatteringEvent→clone→ATLAS smear / CMS smear / Identity copy→SmearedEvent

统一 ATLAS、CMS 和 Identity 三类事件分支，保证不同分析收到一致的 HEPUtils event 接口。

  • 先 clone hard-scattering event。
  • ATLAS/CMS 分支调用对应 detector simulation；Identity 分支直接复制。
  • 通过宏生成对应的 smearEventATLAS、smearEventCMS 和 copyEvent。

证据：ColliderBit/src/smearEvent.cpp:46–71。

MODAnalysis dispatch · 分析执行
SUBFLOW · ANALYSIS DISPATCHSmearedEvent→AnalysisContainer→ATLAS / CMS / Identity→Analysis::run(e)→per-analysis state

把 CBS 选择的分析集合分发到 ATLAS、CMS 和 Identity 的 AnalysisContainer。

  • 每个成功事件调用当前 collider 的全部分析。
  • 保留公共的 Analysis::run(e) 生命周期，新增/扩展分析只需注册并在 YAML 选择。
  • 让多个分析共享相同的 event conversion、detector branch 和结果收集接口。

证据：ColliderBit/src/runAnalyses.cpp:129–148；ColliderBit/src/analyses/AnalysisContainer.cpp:455–474。

MODPer-event analysis state · 事件累积
SUBFLOW · PER-EVENT ACCUMULATIONevent→Analysis::run→cutflow + histogram fill→SR counters→_needs_collection

把 cutflow、histogram 和 signal-region counters 统一纳入每个分析的事件累积状态。

  • Analysis::analyze 标记 _needs_collection 并执行具体分析的 run(e)。
  • Histogram 支持 weighted fill、sumw2、under/overflow、scale/combine 和 histogram-backed SR。
  • cutflow 通过运行时开关和编译期 CUTFLOW 能力控制。

证据：ColliderBit/src/analyses/Analysis.cpp:54–63；开发总结 §5.2、§5.5。

MODCOLLIDER_FINALIZE · 结果提交
SUBFLOW · RESULT COMMITCOLLIDER_FINALIZE→get_results_ptr→collect_results→warning / consistency checks→AnalysisData

明确分析结果只在 loop finalize 阶段提交，避免在事件处理中提前读取不完整结果。

  • 遍历当前 collider 的 analyses map。
  • 调用 get_results_ptr(warning)，触发各分析的 collect_results()。
  • 检查 luminosity、scale 和运行警告，再把 AnalysisData 交给聚合阶段。

证据：ColliderBit/src/runAnalyses.cpp:93–113；ColliderBit/src/analyses/Analysis.cpp:96–134。

MODCollectAnalyses() · 结果聚合
SUBFLOW · ANALYSIS AGGREGATIONATLAS results+CMS results+Identity results→validate SRs→AnalysisDataPointers

新增统一的 ATLAS/CMS/Identity 结果汇总和 cutflow 检查入口。

  • 清空并合并三个 analysis result vectors。
  • 首次收集时校验每个分析至少有一个 signal region。
  • 按 CBS 的 check_cutflow 和 normalization 选项输出 cutflow。

证据：ColliderBit/src/ColliderBit_eventloop.cpp:451–514；开发总结 §5.2。

PARTcalc_LHC_LogLikes() · Likelihood 输入
SUBFLOW · LIKELIHOOD EVALUATIONAnalysisData + xsec + n_mc→regular / FullLikes→covariance / marginalisation→SR loglikes→per-analysis map

当前总图只展开了 CBS 进入公共 likelihood 接口的部分；具体 covariance、FullLikes 和 batch 重算逻辑仍属于下一级细节图。

  • 接收 AnalysisData、cross section、MC event count 和 estimator。
  • 支持 regular/FullLikes、covariance、marginalisation 和 alternative likelihood terms。
  • batch 合并完成后重新调用该层，而不是合并 per-file loglike。

证据：ColliderBit/src/LHC_likelihoods.cpp:1373–1410；开发总结 §5.3–§5.4。

OPTRivet / Contur · 可选分支
SUBFLOW · OPTIONAL CONTUR PATHwithRivet / withContur→init nested functors→Rivet measurements→pool loglikes→optional output

这是 CBS 保留的可选后端路径，不是主 CBS 输出链的必需修改。

  • 运行时根据 withRivet/withContur 初始化并接入 nested functions。

MODFinal values · 最终结果视图
SUBFLOW · FINAL RESULT VIEWSevent_count+analysis_results+analysis_loglikes+Contur pools→final values

把 loop、analysis 和 likelihood 的结果组织成输出模块可以消费的统一参数。

  • 收集 CBS event count、combined loglike、analysis results 和 per-analysis loglikes。
  • 在启用 Contur 时同时收集 total 和 per-pool 信息。

证据：ColliderBit/examples/solo.cpp:558–572。

ADDSoloOutput::emit_outputs() · 输出 API
SUBFLOW · OUTPUT APIfinal values→emit_outputs→screen summary+JSON writer→published result

新增统一的屏幕摘要和文件输出 API，解除 CBS 结果对内部 C++ 对象生命周期的依赖。

  • 按 OutputConfig 决定是否打印屏幕摘要。
  • 按配置写出 JSON，并承接 batch 的 sampling advice。
  • 统一处理 analysis、likelihood、Contur 和 SR 结果。

证据：ColliderBit/examples/solo_output.cpp:376–405；开发总结 §5.3。

ADDCBS_output.json · 结果 schema
SUBFLOW · JSON PAYLOADAnalysisData→schema_version→analyses + SRs→cutflows + histograms→terms + variants→CBS_output.json

新增稳定的 cbs-solo-loglike-v1 输出契约。

  • 输出 run summary、analysis metadata、signal regions、cutflows 和 histograms。
  • 输出 n_sig_MC、MC/statistical error、scaled signal、likelihood terms、variants 和 predefined sets。
  • batch 时额外输出 sampling advice；启用 Contur 时输出 pools 和 total loglike。

证据：ColliderBit/examples/solo_output.cpp:406–685；开发总结 §5.3、§5.5。
