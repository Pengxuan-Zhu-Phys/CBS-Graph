main surface原型 SUSYRun2当前 CBS framework对 main 修改树的解释
进程入口 / CLImain 直接检查 argc < 2，读取 argv[1]，并在函数内输出 usage。调用 SoloCLI::parse_command_line()，通过 CommandLineStatus 区分 help、error 和 run。原子块从“参数读取”变成“CLI helper + 状态分支”；对应 Startup 分支前两个 block。
配置 / 输入YAML::LoadFile、analysis/settings 提取、event_file 和 HepMC 后缀检查都集中在 main。由 SoloInput::parse_and_prepare_input() 生成 PreparedInput，统一处理 defaults、文件模式、截面和文件存在性。新增文件边界，main 只消费规范化数据；对应 Input 分支的 handoff 和 input preparation。
运行模式单个 event_file 运行，没有 processes 分支。增加 PreparedInput.processes、SoloBatch::run_and_merge() 和 sampling advice。新增 batch 早分流，避免把多文件合并逻辑混入 single-file event loop。
Likelihood / backend入口路径固定使用 calc_LHC_LogLikes_full，并把 FullLikes 当作必需 backend。根据 use_FullLikes 选择 regular 或 FullLikes；只在启用时解析 FullLikes backend 依赖。main 从固定 functor 改成运行时策略选择；对应 likelihood selector、option propagation 和 dependency wiring。
Loop / diagnosticsmax_nEvents = 1000000000，且 print_cutflows 固定为 true。使用 INT_MAX、关闭 convergence checks，并增加 check_cutflow/check_histogram runtime policy。把 CBS 的“处理到输入结束”和诊断开关显式化；对应 Runtime policy 和 loop policy。
结果 / 输出main 内部拼接 stringstream，直接打印 analysis/SR/likelihood summary。组装统一结果参数，调用 SoloOutput::emit_outputs()，可输出 screen summary 和 cbs-solo-loglike-v1 JSON。输出从一次性终端文本变成可复用 API + machine-readable contract；对应 Result assembly、Output API 和 JSON payload。

Effectbatch-specific merge logic stays out of the single-file path.
